# 常见问题


## 面板安装、迁移与更新

安装、旧版迁移和后续更新使用同一个管理菜单。服务器上执行：

```bash
curl --fail --location --retry 3 https://raw.githubusercontent.com/shanlianyun/flux-panel/main/panel_install.sh -o panel_install.sh && bash panel_install.sh
```

- 新安装选 `1`，必须使用专用空目录。
- 原作者版本迁移选 `7`，并核对旧部署目录；不要先卸载或删除数据卷。
- fork 后续更新选 `2`。该选项不会自动迁移旧版。
- 单独备份选 `4`；恢复中断的迁移/更新选 `8`。

需要 Python 3.8+ 和 Docker Compose v2。迁移指南说明[支持范围、备份及失败恢复](https://github.com/shanlianyun/flux-panel/blob/main/docs/migrate-from-original.md)。如果系统结构或运行配置不受支持，菜单会停止，不要通过重新安装绕过检查。

管理脚本默认使用数字菜单，直接运行即可：

```bash
bash panel_install.sh
```

按菜单选择：`1` 全新安装、`2` 更新 fork、`4` 备份、`7` 旧版迁移、`8` 恢复中断操作。更新和迁移会在替换前备份并执行健康检查；出现中断时选择 `8`，不要直接卸载或删除数据卷。命令行子命令和 `--tag` 仅供自动化维护使用。

## 节点管理脚本

### 全新机器：复制一条安装命令

管理员先在“网站配置 → 节点连接地址”保存完整入口，例如 `https://node.example.com:443`（公网）或 `http://192.0.2.1:6365`（受控内网），必须带协议，不带路径。公网入口先配置有效证书及 WebSocket 反向代理。

然后在面板新增节点，在“节点监控/节点管理”点击该节点的安装按钮并复制命令，以 root 身份在新机器执行。命令自动带上协议、地址和节点密钥，不需要先 `export`，也不需要修改 systemd。管理脚本会下载到专用 `/root/flux-node.sh`，下载成功才执行；GOST 二进制仍须通过 SHA-256 和可执行版本检查。

若旧面板配置仍是 `域名:端口`，复制命令时会提示填写完整地址，不会猜测协议。只需在面板修正一次，再重新复制命令。该设置不会自动改变已运行节点，先保留旧节点的 HTTP/WS 通道。仅让网页显示 HTTPS 不代表节点入口已经配置正确。

安装命令包含节点密钥，请勿公开分享，也不要用其他节点的命令安装新节点。已有节点仍使用下方数字菜单选 `2`，不要重复执行新节点安装命令。

### 已有机器：数字菜单管理

在面板的“节点管理”页面复制安装命令。新节点执行面板复制的命令即可；已有节点先确认目标 Release 发布成功，再下载本 fork 的脚本打开数字菜单（不要继续使用原作者旧脚本）：

```bash
curl --fail --location --retry 3 https://raw.githubusercontent.com/shanlianyun/flux-panel/main/install.sh -o flux-node.sh && bash flux-node.sh
```

菜单选项：

```text
1. 安装
2. 更新
3. 卸载
4. 屏蔽 http/tls/socks 协议
5. 退出
6. 修改面板连接地址 / 迁移 HTTPS
```

脚本执行完成后不会删除自身；通过面板命令安装的机器也可直接运行 `bash /root/flux-node.sh` 打开同一个菜单。已有节点选择 `2` 更新，不要选择 `1` 覆盖配置。更新会短暂停止并重启 GOST；建议先选择一台灰度节点验证，再分批更新其他节点。下载校验失败或新二进制无法启动时，脚本会保留/恢复旧二进制。

### 旧节点迁移 HTTPS/WSS：选择 6

原作者节点先用本 fork 的菜单 `2` 升级程序；已经升级过的不必重复更新。确认新入口已配置有效证书、后端及 WebSocket 反代，再重新下载上面的管理脚本：

1. 选择 **`6. 修改面板连接地址 / 迁移 HTTPS`**。
2. 输入完整新入口，例如 **`https://node.example.com:443`**，不要带结尾斜杠或其他路径。
3. 核对旧、新地址后输入 `y` 确认。

不需要填写节点密钥、手改 JSON 或 systemd，也不需要卸载重装。脚本保留节点身份、协议屏蔽设置、本地转发配置和二进制；自动将地址与 HTTPS/WSS 协议分别保存。`2. 更新` 默认只更新程序，不会自动迁移地址或协议。

迁移需要 Python 3、curl 和 systemd。脚本先检查证书和 `/flow/test` 后端响应，不通过就不重启原服务；通过后才备份、切换并重启 GOST。只有本次启动的节点通过新入口建立真实 WebSocket 连接才显示“迁移完成”，握手失败或约 30 秒内未确认连接会恢复原配置并尝试重启原服务。**重启可能中断当前连接，先灰度一台，再逐台操作；成功后仍须验证实际转发和流量上报。**

备份位于节点 `/etc/gost/endpoint-backup.*` 的私有目录，含节点密钥，不要公开。若提示自定义 systemd 配置冲突、回退失败或残留迁移锁，请先停止批量操作并排查，不要改选安装/卸载绕过。断电、强制杀进程等无法保证自动回退，见[旧节点升级与迁移恢复说明](https://github.com/shanlianyun/flux-panel/blob/main/docs/legacy-node-upgrade.md#迁移中断或回退失败)。保留原 HTTP/WS 入口，直到所有旧节点迁移验证完成。

这与仅面板维护不同：面板维护或重启期间，节点本地已经运行的转发不会停止；控制通道和状态上报会暂时中断，面板恢复后节点自动重连并同步有效规则。维护期间不能通过面板执行新的规则变更。

节点升级后可使用以下命令检查：

```bash
/etc/gost/gost -V
systemctl is-active gost
systemctl status gost --no-pager
journalctl -u gost -n 50 --no-pager
```

### 卸载后重新安装同一个节点

这不是日常更新方式。只有明确要清空此机器的节点配置时才卸载；**卸载会停止转发并删除 `/etc/gost` 中的密钥、本地规则及自定义设置**。先备份 `/etc/gost` 和 systemd 配置，并安排维护窗口。

1. 先确认修复版本的面板镜像与节点 Release 已发布，更新面板；在网站配置保存正确的完整节点连接地址。
2. 保留面板上的原节点记录，不要删除或重新创建。先停止使用同一身份的其他机器，避免两台机器争用同一个节点连接。
3. 在要重装的机器下载脚本并打开数字菜单：

   ```bash
   curl --fail --location --retry 3 https://raw.githubusercontent.com/shanlianyun/flux-panel/main/install.sh -o flux-node.sh && bash flux-node.sh
   ```

4. 选 `3. 卸载`，确认输入 `y`。脚本只删除此前文档提供的标准 `99-panel-https.conf` 协议修正片段，不删除自定义 drop-in；若自定义文件覆盖协议，需要自行核对。
5. 回到面板的**同一条节点记录**，点击安装并重新复制命令，在机器上整条执行。无需另设环境变量。
6. 确认脚本显示“已连接面板”、页面在线，再检查原有效规则和实际 TCP/UDP 转发；重连会按面板数据库同步规则，不需要逐条编辑确认。暂停、失效规则不能当作活动规则恢复。本地自定义内容不在面板数据库中，不能靠重连自动找回。

面板不可用时，刚卸载重装的空节点尚无可供恢复的本地转发，必须等面板恢复同步。这与“已有规则在面板维护时继续转发”是不同情况。

### aaPanel 配置 HTTPS/WSS 节点入口

推荐为节点入口单独建立一个域名站点，指向管理面板主机，申请有效 HTTPS 证书，再反代到本机后端。对于原部署后端仍映射到 `6365` 的主机，目标为 `http://127.0.0.1:6365`；自定义端口请按实际映射修改。fork 全新部署若没有映射后端端口，应先按自己的部署方式提供本机可达的后端入口，不要照抄不存在的端口。

在 aaPanel 对应站点的反向代理中启用 WebSocket 支持，保留原路径和查询参数。等效 Nginx 代理片段如下；应修改现有代理块，不要重复添加冲突的 `location /`：

```nginx
location / {
    proxy_pass http://127.0.0.1:6365;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
}
```

必须能将 `/system-info` 的 WebSocket 握手和 `/api/v1/` 的节点上报送到后端，不要将其改写到登录页或静态首页，也不要加浏览器挑战、额外 Basic Auth。代理应保留 `X-Node-Secret`、`X-Node-Capabilities` 请求头；不要把节点密钥写进示例或公开日志。

检查并重载 aaPanel 配置后，在面板“节点连接地址”填写 `https://你的节点入口域名:443`，再复制安装命令。保留旧节点所需的原 HTTP/WS 入口，待逐台验证迁移后再关闭；不要为了新节点改动而中断旧节点。

### 服务已启动但面板显示离线

`systemctl is-active gost` 返回 `active` 只表示进程运行，不表示已通过面板认证。新版安装脚本观察本次服务启动的连接日志，分别提示连接成功、失败或尚未确认；连接检查不会发起第二个节点会话，也不会因面板离线停止本地服务。

```bash
systemctl is-active gost
systemctl show gost -p Environment --value | grep -oE 'GOST_PANEL_SCHEME=[^ ]+'
journalctl -u gost -n 40 --no-pager
```

对于 `https://` 入口，服务环境应为 `GOST_PANEL_SCHEME=https`。若日志为 `websocket: bad handshake`，新版节点会附上 HTTP 状态码：`200` 常见于代理到了网页，`301/302` 表示重定向，`400` 常见于 Upgrade 未正确转发，`401/403` 需检查节点身份或代理访问限制，`404` 检查路径，`502` 检查后端可达性。状态码只能帮助定位，不能单独确定根因。

证书错误应检查域名、证书链和机器时间，不要关闭 TLS 校验，也不要因 HTTPS 失败自动退回明文。若存在旧的 systemd 自定义 drop-in，请检查是否覆盖了安装命令指定的协议。不要公开粘贴含节点密钥的安装命令或完整配置。

## 原作者旧节点能否继续使用

面板升级不等于节点升级，原作者节点可以先保持运行，但属于有限兼容：

- 新面板保留旧版密钥参数认证、控制命令及 HTTP 流量上报格式，不要求节点等待面板握手后才运行本地规则。
- 面板维护只中断管理通道，不主动停止节点上的现有转发。这不代表节点服务本身重启、宕机或配置错误也不会中断转发。
- 旧节点会忽略新版安全暂停配置。存在暂停规则时，面板会拒绝向旧节点下发可能重新打开监听的限速更新；需先升级入口节点并确认在线，再修改限速。只修改流量、到期时间等且不改变限速绑定的操作不受此保护拦截。
- 旧节点在重启后可能重新监听本应暂停的规则；面板无法远程修补旧二进制的本地启动逻辑。若重连清理时缺少某个协议配置，面板宁可拒绝补建，也不会把暂停规则作为活动监听创建。此时恢复操作可能报缺少服务，不能视为已完整恢复，应先升级节点，再核对 TCP/UDP 配置和暂停状态。
- 旧、新节点可能报告相同版本号，不能仅凭页面版本号或 `gost -V` 判断是否完成升级。新版通过已认证的连接明确报告安全暂停能力；未报告的节点按旧节点处理。
- 升级过程中，旧节点需要原来的 HTTP/WS 通道。先保留旧地址和端口，待节点逐台升级并验证 HTTPS/WSS 后，再收紧入口；不要先强制所有旧节点使用它们尚不支持的 WSS。

推荐顺序：**确认修复版本发布完成 → 更新面板并验证旧节点在线 → 在一台非关键节点下载本 fork 脚本、选 `2` → 验证转发、暂停/恢复和面板断线 → 逐台更新其余节点**。节点更新会重启 GOST，可能中断该节点上的现有连接；面板离线期间继续转发的保证，不等于节点升级零中断。不要使用 `1. 安装` 或卸载重装代替更新。

## 日志查看

### 查看后端服务日志

当后端服务出现问题时，可以通过以下命令查看实时日志：

```bash
docker logs -f springboot-backend
```

按 `Ctrl+C` 退出日志查看

### 查看节点日志

当转发功能出现问题时，可以通过以下命令查看gost服务日志：

```bash
journalctl -u gost -f
```

按 `Ctrl+C` 退出日志查看

### 屏蔽 http/tls/socks 协议

⚠️注意：目前已知bug，开启屏蔽后，转发udp会失效，只能转发tcp

屏蔽指定协议的方法，只需要在入口执行。出口无需执行

1️⃣ 编辑配置文件

打开 /etc/gost/config.json，添加以下字段：
```
"http": 1,
"tls": 1,
"socks": 1
```

2️⃣ 重启服务
```
sudo systemctl restart gost
```

3️⃣ 检查状态（可选）
```
sudo systemctl status gost
```

- 说明：
  - 0 或不添加 → 不屏蔽对应协议
  - 1 → 屏蔽对应协议

完整的json文件
```
{
  "addr":"127.0.0.1：6365",
  "secret":"doraemon",
  "http":1,
  "tls":1,
  "socks":1
}
```
