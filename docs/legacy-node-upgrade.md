# 原作者旧节点的兼容边界与升级

面板更新不会替换节点程序。原作者 BrunuhVille 节点可先保留运行，但不能认为只升级面板就获得了节点侧所有修复。

## 升级前确认

1. 确认包含旧节点兼容保护的面板镜像和目标 GOST Release 均构建成功。仅合并代码、下载新版脚本，不代表二进制已经发布；不要在 Release 仍指向上一版时批量更新。
2. 安全备份节点的 `/etc/gost/config.json`、`/etc/gost/gost.json` 和 systemd 服务文件；不要上传其中的节点密钥。保留面板数据库与配置备份。
3. 先更新面板，核对旧节点在线、现有转发和流量上报。迁移期间保留旧节点使用的 HTTP/WS 地址、端口和原有密钥；不要先切断旧控制通道。
4. 选择非关键节点安排维护窗口。节点更新会重启 GOST，不能保证该节点上的现有连接不中断；这与仅管理面板维护期间继续转发是不同场景。

## 数字菜单更新

确认发布完成后，在选定的节点执行：

```bash
curl --fail --location --retry 3 https://raw.githubusercontent.com/shanlianyun/flux-panel/main/install.sh -o flux-node.sh && bash flux-node.sh
```

选 **`2. 更新`**。不要选安装或卸载；旧脚本的更新仍然下载原作者程序，必须先换成本 fork 的管理脚本。新版更新保留节点地址、密钥、协议屏蔽设置和转发配置，验证 SHA-256 后才替换二进制；新服务启动失败时尝试恢复旧二进制，但这不代替业务验证。

检查该节点实际承担的 TCP/UDP、入口/出口转发，以及暂停、恢复、节点重启后暂停状态。再仅断开测试面板控制通道，验证已有连接与新连接继续转发；面板恢复后验证自动重连和有效规则同步。全部通过再逐台升级，避免同时重启所有入口/出口节点。

## 数字菜单迁移 HTTPS/WSS

先配置有效证书及支持 WebSocket 的后端反向代理。已完成程序更新的旧节点，重新下载上面的管理脚本后：

1. 选 **`6. 修改面板连接地址 / 迁移 HTTPS`**。
2. 输入完整新入口，例如 `https://node.example.com:443`，不要带路径或结尾斜杠。
3. 核对旧、新入口，输入 `y` 确认；节点重启可能短暂中断当前连接。

不需要重复选 `2`，也不用填密钥、手改文件或卸载重装。菜单 `6` 不下载/替换二进制，只修改 `config.json` 中的 `addr`，并通过专用 `99-flux-panel-endpoint.conf` drop-in 保存 `GOST_PANEL_SCHEME`。节点密钥、其他 JSON 字段、`gost.json` 转发规则、原 unit 和自定义 drop-in 保持不变。普通菜单 `2` 默认保留地址与协议。

迁移需要 Python 3、curl、systemd。脚本先验证 TLS 证书和 `/flow/test` 的 HTTP 200 / `test` 响应，不通过则不重启原服务。通过后创建权限 `700` 的 `/etc/gost/endpoint-backup.*` 备份目录，再切换并验证本次启动的真实节点 WebSocket 会话；握手失败、启动失败或约 30 秒未确认连接会恢复原配置并尝试重启原服务。若服务依赖自定义 `EnvironmentFile`、协议被其他 drop-in 覆盖或托管路径包含自定义内容，脚本会拒绝迁移，不会覆盖用户配置。

面板“节点连接地址”仍应保存完整 HTTPS 入口，供以后生成新节点命令；修改面板设置不会自动改变已有节点。先灰度一台，验证在线、入口/出口 TCP/UDP 及流量上报，再逐台迁移；全部通过后才可关闭旧 HTTP/WS 通道。显式输入 HTTP 入口时须另外输入 `HTTP` 确认明文连接，不会自动从 HTTPS 降级。

## 迁移中断或回退失败

备份包含密钥，不要公开分享。每次迁移的目录会在终端显示，内含原 `config.json`，若迁移前已有专用 drop-in，还会有原 `endpoint.conf`。脚本只回退它修改的这两处，不改节点规则文件、二进制或其他 systemd 配置。恢复服务成功仅表示进程运行，仍须检查旧入口及实际转发。

正常报错和可捕获的中断会尝试回退；断电、`kill -9` 或文件系统故障无法保证自动恢复。此时不要直接重试、卸载或删除备份：先确认没有仍在执行的迁移进程，再核对本次备份。由管理员将备份的 `config.json` 恢复到 `/etc/gost/config.json`；若有 `endpoint.conf` 则恢复到 `/etc/systemd/system/gost.service.d/99-flux-panel-endpoint.conf`，若没有则仅删除本次新建的该专用文件，保留其余自定义配置。随后执行 `systemctl daemon-reload`、`systemctl restart gost`，检查日志与实际转发；确认恢复完成后再移除空的 `/etc/gost/.endpoint-migration.lock` 目录。不要在不了解备份来源时自动恢复或批量重试。

## 有限兼容，不误启用暂停规则

新面板保留旧节点认证和控制/上报协议；运行中的规则不会因为面板离线而被主动关闭。但旧节点忽略 `metadata.paused`，更新暂停配置时会重新监听；节点本身重启时也不能依赖它保持暂停。

新版节点在已认证的 WebSocket 握手中报告 `X-Node-Capabilities: paused-services-v1`，面板不依赖可能重复的版本号。没有此能力的连接：

- 仍允许基本心跳、活动规则同步和原有控制命令。
- 存在暂停规则时，拒绝限速绑定变更，通常在保存权限前返回升级提示。
- 发送命令时再次检查当前连接，拦截可能绑定监听的暂停配置，防止会话替换绕过前置检查。
- 重连同步失效时可暂停已有服务，但不把缺失服务作为暂停配置发给旧解析器。缺失的 TCP/UDP 配置可能导致后续恢复失败，需要升级后核对、修复配置，不能把缺少服务的报错当作完整恢复。
- 若保存后连接发生变化或远程操作失败，返回“权限已保存，但节点限速同步失败”，不谎报全部成功。此时数据库配置和节点运行配置可能不同，必须核对后再开放业务。

这些保护无法修改旧二进制本身的行为。需要完整暂停持久化和节点侧安全加固时，仍须升级节点，不应长期混用。

## 验证范围

对照原作者仓库提交 `673f74ffea8f4181d0b81e83a75ec201819cd6ab`，在本机隔离环境用其源码实测：控制连接真正关闭后，已有 TCP 连接与新 TCP 连接仍可转发；同时复现了旧解析器忽略暂停标记、重新打开监听的问题。新版回归测试覆盖握手能力、旧节点配置拦截、正常活动规则、离线节点和会话替换，以及真实控制断线后的转发。

这是源码与本机模拟验证，不等于已验证每一台生产节点的历史二进制、网络环境或 UDP/隧道组合；正式部署仍需单节点灰度。
